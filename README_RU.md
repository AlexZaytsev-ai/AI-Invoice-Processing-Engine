# AI Invoice Processing Engine

## Описание проекта

AI Invoice Processing Engine — это автоматизированный workflow, разработанный в n8n для обработки входящих инвойсов.

Система автоматически получает инвойсы из Gmail, извлекает текст из PDF-документов, анализирует данные с помощью AI, проверяет бизнес-правила компании и создаёт или обновляет записи в реестре инвойсов.

---

# Бизнес-задача

Компания ежедневно получает большое количество счетов на оплату (Invoice).

Ручная обработка каждого документа требует:

- открыть PDF;
- проверить поставщика;
- сверить банковские реквизиты;
- проверить наличие инвойса;
- создать или обновить запись;
- уведомить ответственного сотрудника.

Такой процесс занимает много времени и увеличивает вероятность ошибок.

---

# Решение

Workflow полностью автоматизирует обработку входящих инвойсов.

Автоматизация выполняет:

- получение письма из Gmail;
- извлечение текста из PDF;
- AI-анализ документа;
- подготовку структурированных данных;
- поиск поставщика;
- проверку банковского счёта;
- поиск существующего инвойса;
- создание новой записи;
- обновление существующей записи;
- уведомление менеджера.

# Ключевые архитектурные решения

### AI Processing

AI используется только для извлечения и структурирования данных из документа.

AI не принимает бизнес-решения.

---

### Business Validation

После обработки AI данные проходят последовательную проверку:

- поиск поставщика;
- проверка банковского счёта;
- поиск существующего инвойса;
- проверка изменений.

Все решения принимаются детерминированной логикой workflow.

---

### Supplier Registry

Реестр поставщиков используется как единый источник достоверных данных (Single Source of Truth).

По нему проверяются:

- существование поставщика;
- банковские реквизиты.

---

### Business Key

Поставщики идентифицируются по:

```
supplier_inn
```

Инвойсы идентифицируются по составному Business Key:

```
supplier_inn + invoice_number
```

Это предотвращает создание дубликатов.

---

### Versioning

Если инвойс уже существует, workflow определяет, изменились ли бизнес-данные.

При наличии изменений:

- запись обновляется;
- увеличивается номер версии;
- обновляется дата изменения.

Если изменений нет — workflow завершается без обновления.

---

### Manual Review

Автоматическая обработка останавливается в двух случаях:

- поставщик отсутствует;
- банковский счёт не совпадает.

В этих ситуациях решение принимает сотрудник.
