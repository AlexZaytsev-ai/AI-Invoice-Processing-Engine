# Запуск демоинтерфейса

[Главный README](../README.md) · [Публикация](deployment.md) · [API и backend](api-contract.md)

Приложение работает на вымышленных данных. Для запуска демоверсии не нужны n8n, PostgreSQL, credentials или внешние сервисы.

## Требования и установка

Нужен Node.js ветки **24, начиная с 24.15**, или **22, начиная с 22.22.2**. Приложение проверено на Node.js 24.20.0. Зависимости зафиксированы в [package-lock.json](../package-lock.json).

В корне репозитория:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173/**. На macOS и Linux используйте `npm` вместо `npm.cmd`. В Windows вариант `npm.cmd` работает и при ограничении запуска PowerShell-скриптов.

Выберите сценарий и нажмите «Обработать тестовый счёт». В интерфейсе есть состояния ожидания, обработки, отмены, ошибки и результата. Каждый запуск начинается с независимого тестового состояния; реальные записи не создаются.

## Свой PDF

Можно выбрать или перетащить **один PDF до 10 МБ**. В браузере проверяются размер, тип и сигнатура файла. В деморежиме содержимое не извлекается, документ не отправляется, выдуманный результат не подставляется.

Для реального извлечения данных нужен отдельно реализованный backend. Подготовленный адаптер и порядок подключения описаны в [контракте API](api-contract.md).

## Доступ с телефона по локальной сети

Запустите вместо обычного `dev`:

```powershell
npm.cmd run dev:lan
```

Vite слушает порт **5173** на сетевых интерфейсах компьютера. Подключите телефон к той же Wi-Fi сети и откройте адрес `Network`, который вывел Vite, например **http://192.168.0.107:5173/**. Это пример адреса: IP может измениться при переподключении.

Если страница с телефона не открывается, проверьте, что устройства находятся в одной сети и роутер не изолирует клиентов. Брандмауэр Windows должен разрешать входящие TCP-подключения на порт 5173 из локальной подсети; изменение правила может требовать прав администратора.

`dev:lan` не публикует сайт на хостинге и не создаёт интернет-туннель. Обычный `dev` остаётся доступен только на компьютере. Для остановки сервера нажмите `Ctrl+C` в его терминале.

## Проверка и production-сборка

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`test` проверяет сценарии, действия интерфейса, валидацию PDF, API-адаптер и контракт ответа. Тесты backend используют сетевые заглушки и не обращаются к реальным сервисам. `build` запускает проверку TypeScript и создаёт `dist/`.

Адрес preview: **http://127.0.0.1:4173/AI-Invoice-Processing-Engine/**. Production-сборка использует путь репозитория, а `dev` и `dev:lan` — корень `/`. Для проверки именно публичной демоверсии используйте `npm.cmd run build:pages` вместо `build`: эта команда принудительно сохраняет деморежим. Подробнее — в [инструкции публикации](deployment.md).

## Структура интерфейса

| Файл или каталог                                          | Назначение                                            |
| --------------------------------------------------------- | ----------------------------------------------------- |
| [src/App.tsx](../src/App.tsx)                             | Экран, загрузка документа и представление результатов |
| [src/styles.css](../src/styles.css)                       | Адаптивная вёрстка и оформление                       |

| [src/api/resultContract.ts](../src/api/resultContract.ts) | Проверка ответа backend во время выполнения           |

Проверки расположены рядом с кодом в файлах `.test.ts` и `.test.tsx`. В интерфейсе нет внешних шрифтов, CDN, аналитики, авторизации и оплаты. Согласование счетов в его состав не входит.
